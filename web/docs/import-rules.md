# Importing and parsing transcripts

> **Status (2026-11-20).** Extracted from the Apple app's source. This document does not depend on the owner's later decisions and is ready to build from. See `../HANDOFF.md`, section 5.

## Summary

- The Apple app turns three kinds of input into sessions: files (`.md`, `.txt`, `.json`), clipboard text, and the strings returned by its capture browser. All parsing is in one file, `apple/SessionVault/Importers.swift` (469 lines); the glue around it is in `Views/ImportSheet.swift` and `Views/LinkCaptureView.swift`.
- Four parsers run in a fixed order: ChatGPT export JSON (only for `.json` files), puller Markdown, share-page text (`You said:` / `Claude responded:`), generic text with speaker markers. Everything is line-based text heuristics. Roles and the provider label come from text, never from page markup.
- Part A (section 2) states that behaviour exactly, including the Swift string semantics a port has to reproduce: which characters a trim removes, and that lengths are counted in user-perceived characters.
- Part B (section 3) lists 18 defects, D1 to D18, each confirmed by running the real importer on synthetic input, and the rules W1 to W15 the web app follows instead. The two headline defects: input with Windows line endings collapses into one message (D1), and a whole-page capture is stored as ONE message whose provider label comes from a keyword scan, so a Gemini page that mentions Claude is labelled Claude (D2).
- Part C (section 4) lists what differs because the target is a web app: bytes must be decoded explicitly, the clipboard is not readable at will, the database rejects some characters, imported text is untrusted.
- `fixtures/import/` holds 57 golden fixtures with the result of the real importer for each. 23 are parity tests (web must equal Apple), 31 record a defect together with the web target, 3 are optional web extensions. They are the acceptance tests of the port.
- A TypeScript port written from these rules was compared with the real Swift importer on 30,000 random inputs with no difference, so the rules below are complete enough to implement from.

File import in detail:

- Allowed types in the picker: `UTType.json`, `.plainText`, `.text`, and the type registered for the extension `md` (`Views/ImportSheet.swift:26-30`). Multiple selection is on. `.text` is the broad "any text" type, so HTML, RTF or source files can be picked and are then parsed as plain text (inference from the type hierarchy; not run). The drop target has no type filter at all.
- `importFiles` loops over the URLs: start security-scoped access, read the whole file with `Data(contentsOf:)`, skip the file silently if that fails, call `parse(data:filename:)` with the last path component as file name, insert every returned session, count them. One status line covers all files; there is no per-file result.
- Decoding is decided by the file name extension only, never by content or media type:

```text
parse(data, filename):                                  // Importers.swift:24-33
    ext = lowercase(extension of filename)
    if ext == "json"
       and JSONSerialization can parse data             // UTF-8, UTF-16 or UTF-32, with or without a byte-order mark (run)
       and parseChatGPTExport(object) is not nil:       // 2.5.1
        return those sessions
    text = data decoded as strict UTF-8                 // one leading byte-order mark is removed (run)
    if decoding failed or text is empty: return []
    return parseText(text, title = filename without its extension)
```

- Extension and title follow `NSString.pathExtension` / `deletingPathExtension` (run): the extension is the text after the last dot, provided the dot is not the first character and the text after it is not empty and contains no space.

| File name | Extension | Title used |
|---|---|---|
| `notes.txt` | `txt` | `notes` |
| `my.session.notes.md` | `md` | `my.session.notes` |
| `conversations.JSON` | `json` | `conversations` |
| `README` | none | `README` |
| `.notes`, `.json` | none (leading dot) | `.notes`, `.json` |
| `name.` | none | `name.` |
| `Mr. Smith notes` | none (space after the dot) | `Mr. Smith notes` |

Clipboard in detail (`Views/ImportSheet.swift:195-226`):

```text
text = clipboard string
if text is missing or full trim(text) is empty: status "Clipboard is empty."; stop
trimmed = full trim(text)
if trimmed contains no "\n" and no " " and contains "." and length(trimmed) < 500:
    candidate = trimmed, prefixed with "https://" if it does not contain "://"
    if URL(string: candidate) has a host:
        put trimmed into the link field; status "That's a link <U+2014> opening it in the capture browser."
        open the capture browser at that URL; stop                      // nothing is imported
sessions = parseText(text, title: "Pasted session")                     // the UNtrimmed text
for each session: if its provider is Other, replace it with the picker value   // picker default: Claude (ImportSheet.swift:16)
insert each; status "Imported N session(s) from clipboard."
```

The picker never overrides a provider the parser found (run: picker ChatGPT, text mentioning "gemini", result Gemini). The help text under it reads: `No need to pick first <U+2014> the provider is detected automatically from links and transcript content. This picker only labels pastes that can't be identified.` (`Views/ImportSheet.swift:92`).

### 2.3 String semantics the rules depend on

These are properties of Swift and Foundation, verified on the toolchain above. A port that uses JavaScript's `trim()`, `length` and `\s` without thought will differ.

| Operation in the code | Exact meaning |
|---|---|
| Split into lines | `components(separatedBy: "\n")`: at every LF and nowhere else. A CR stays at the end of its line. `"a\n"` gives two lines, `"a"` and `""`. |
| inline trim (`.whitespaces`) | Removes from both ends any of these 19 code points (found by testing every Unicode scalar): U+0009, U+0020, U+00A0, U+1680, U+2000 to U+200B, U+202F, U+205F, U+3000. It does NOT remove CR, LF, U+FEFF. Note U+200B (zero width space) IS removed, unlike JavaScript `trim()`. |
| full trim (`.whitespacesAndNewlines`) | The 19 above plus U+000A, U+000B, U+000C, U+000D, U+0085, U+2028, U+2029 (26 in all). It does not remove U+FEFF. |
| length (`String.count`) | Number of user-perceived characters (extended grapheme clusters). An emoji counts 1, a letter with a combining accent counts 1, and the pair CR LF counts 1. JavaScript `length` counts UTF-16 units and gives larger numbers. Use `Intl.Segmenter` with `granularity: "grapheme"`. |
| `lowercased()` | Unicode lower-casing, independent of locale. All marker words are ASCII. |
| `hasPrefix`, `==`, `contains` | Compare whole characters. Two consequences: `"a\r\nb".contains("\n")` is false (run), and a marker immediately followed by a combining mark is not found. Otherwise they behave like `startsWith`, `===`, `includes`. |
| JSON | `JSONSerialization`: numbers become doubles; a top-level scalar is an error. |

JavaScript equivalents: inline trim = remove, at both ends, any character of the class made of tab, space, U+00A0, U+1680, U+2000 to U+200B, U+202F, U+205F and U+3000; full trim = that class plus LF, U+000B, U+000C, CR, U+0085, U+2028 and U+2029. Write the class with escapes in source code; `trim()` and `\s` are close but not equal (they miss U+200B and U+0085 and add U+FEFF). Fixture 23 ends with a zero width space and a U+0085 that only the exact sets remove.

### 2.4 Speaker markers

`roleMarker(in:)`, `Importers.swift:392-421`. Input: one line. Output: a role and the text that followed the marker on the same line, or nothing.

```text
c = inline trim(line); if c is empty: no marker
remove every leading "#" from c; c = inline trim(c)
delete EVERY occurrence of "**" in c                    // not only around the label (D7)
l = lowercase(c)
for (name, role) in this order:
      "you said" user, "claude responded" assistant, "claude said" assistant, "chatgpt said" assistant, "gemini said" assistant,
      "user" user, "human" user, "you" user, "me" user,
      "assistant" assistant, "claude" assistant, "chatgpt" assistant, "gpt" assistant, "gemini" assistant, "ai" assistant,
      "system" system
    if l == name and name is one of {user, human, assistant, claude, chatgpt, gemini}: return (role, "")     // "bare" marker
    if l starts with name + ":": return (role, inline trim(c without its first length(name) + 1 characters))
no marker
```

Observed (run), with a body line after each:

| Line | Result |
|---|---|
| `User: q`, `USER: q`, `user:q`, `User:` | user; text `q` (or nothing) |
| `Human: q`, `You: q`, `Me: q` | user |
| `Assistant: a`, `Claude: a`, `ChatGPT: a`, `GPT: a`, `Gemini: a`, `AI: a` | assistant |
| `System: s` | system |
| `Claude said: a`, `ChatGPT said: a`, `Gemini said: a` | assistant |
| `User`, `Human`, `Assistant`, `Claude`, `ChatGPT`, `Gemini` (bare) | marker |
| `You`, `Me`, `GPT`, `AI`, `System`, `You said`, `Gemini said`, `ChatGPT said` (bare) | NOT a marker |
| `## User`, `### Human: q`, `#User: q`, `**User:** q`, `**User**: q`, `**User**` | marker |
| leading tab, spaces or U+00A0 before `User: q`; `  ## **Assistant:**   spaced   ` | marker; text `spaced` |
| `**Assistant:** Use **bold** now` | assistant; text `Use bold now` (the bold markup is gone) |
| `Assistant:a:b` | assistant; text `a:b` |
| `user: admin`, `system: linux`, `ai: true`, `me: too`, `you: there` | marker (any line of that shape, also inside code) |
| `User : q`, `User 1: q`, `User (me): q`, `[User]: q`, `Users: q`, `Username: q`, `AI assistant: q`, `GPT-4: a` | not a marker |
| `- User: q`, `> User: q`, `1. User: q`, `*User:* q`, `__User:__ q`, `# # User: q` | not a marker |
| `User` + U+FF1A (full-width colon) | not a marker |

`You said: x` and `Claude responded: x` reach this function only when the share-page parser returned nothing (2.5.3).

```text
splitLeadingRoleMarker(block):                          // Importers.swift:423-431
    m = roleMarker(first line of block); if none: no marker
    remaining = the other lines joined with "\n"
    if m.rest is not empty: remaining = m.rest + "\n" + remaining
    return (m.role, full trim(remaining))               // may be the empty string (D8)
```

### 2.5 The four parsers

#### 2.5.1 ChatGPT data export

`parseChatGPTExport`, `Importers.swift:281-343`. Reached only for a file whose extension is `json`.

```text
conversations =
    the array itself, if the top level is an array whose elements are all objects (an empty array qualifies)
    [the object], if the top level is an object that has a key "mapping"
    otherwise: not this format
if any conversation's "mapping" is not an object: not this format        // all or nothing (D9)

for each conversation, in order:
    title   = "title" if it is a non-empty string, else "ChatGPT conversation"       // not trimmed
    created = "create_time" if it is a number: seconds since 1970-01-01 UTC, fractions kept; else none
    if "current_node" is a string:
        walk: node = mapping[current_node]; collect it; follow node["parent"] (a string) while that id
              exists in mapping as an object; then reverse the list                  // no cycle check (D9)
    else:
        all values of mapping that are objects, sorted ascending by message.create_time (missing = 0)
        // the dictionary has no order and the sort is not stable (D9)
    for each node:
        skip unless node.message, message.author, message.content are objects and author.role is a string
        parts = content.parts if it is an array, keeping only the elements that are strings
        text = full trim(parts joined with "\n"); skip if empty
        role = user | assistant | system for those three strings, anything else -> unknown
        skip if role is system
        append (role, text)
    skip the conversation if it has no message
    append session(title, provider ChatGPT, created, messages)
if no session: not this format
```

"Not this format" sends the file to the text parsers, which import the raw JSON text as a note (D9). Observed (fixtures 07, 08; run): only the branch that ends at `current_node` is imported; a `tool` author becomes role `unknown`; content without string parts (images, `content_type: "code"` with a `text` field) contributes nothing; a `create_time` given as a string is ignored; JSON `true` as `create_time` becomes 1970-01-01T00:00:01Z (number bridging; ignore).

#### 2.5.2 Puller Markdown

`parsePullSessionsMarkdown`, `Importers.swift:237-277`. The writer is `puller/pull_sessions.py:191-194`: the lines `# <id>`, `Source: <url>`, an empty line, then for each turn its text, an empty line, `---`, an empty line.

```text
lines = text split at "\n"
require: at least 2 lines, lines[0] starts with "# ", lines[1] starts with "Source: "     // exact, case-sensitive, first two lines
title    = inline trim(lines[0] without "# ")
source   = inline trim(lines[1] without "Source: ")
provider = Claude if source contains "claude.ai" (anywhere in the string), else Other
blocks: cut lines[2...] at every line whose inline trim is exactly "---"; full trim each block; drop empty blocks
for each block: splitLeadingRoleMarker(block) -> (role, text); if no marker: (unknown, block)
return session(title, provider, sourceURL = source, no date, messages)      // also with zero messages (D8)
```

Observed (run): `#title`, `source: x`, `Source:x`, a blank line or a space before the header all defeat detection, and the file then goes to the generic parser with the header as a note and `---` left inside the message texts (D11). `----`, `- - -`, `***` are not separators; `---` with surrounding spaces or a tab is. A `---` line inside a turn splits that turn. A role is found only on the first line of a block.

#### 2.5.3 Share-page text

`parseClaudeShareText`, `Importers.swift:93-131`, written for the visible text of a claude.ai share page.

```text
require: the text contains "You said:" or "Claude responded:" anywhere (case-sensitive)
role = none; lines = []
for each raw line of text:
    line = inline trim(raw)
    if line starts with "You said:":            flush(); role = user        // the rest of the header line is discarded
    else if line starts with "Claude responded:": flush(); role = assistant
    else if role is set: lines.append(raw)                                  // text before the first header is dropped
flush()
if no message: this parser does not apply (fall through to the generic parser)
return session(title as passed (not trimmed), provider Claude, no date, messages)

flush(): cleaned = full trim(cleanTranscriptLines(lines) joined with "\n")
         if role is set and cleaned is not empty: append (role, cleaned)
         lines = []
```

The text after `You said:` on the header line is treated as a truncated preview of the lines that follow. When nothing follows, the turn is lost (D6).

`cleanTranscriptLines`, `Importers.swift:72-88`, removes page furniture. It is also applied to every turn of a multi-turn capture (2.6).

```text
kept = []; last = ""
for each raw line:
    line = inline trim(raw)                                    // the trimmed line is what gets stored (D5)
    if line is empty: append "" unless kept is empty or already ends with ""; continue      // blank runs collapse to one
    if line is boilerplate or a time line: continue
    if line == last: continue                                  // equal to the previous KEPT non-empty line, blank lines in between do not matter
    last = line; kept.append(line)
drop trailing "" entries
```

- Boilerplate, exact line (case-sensitive): `Report`, `Copy`, `Retry`, `Share`, `Claude` (`Importers.swift:56-58`).
- Boilerplate, line starts with (case-sensitive): `Shared by `, `This is a copy of a chat`, `Content may include unverified`, `Shared snapshot may contain`, `Ask Claude your own question`, `Claude can make mistakes` (`Importers.swift:47-54`).
- Time line: the whole line matches `^\d{1,2}:\d{2}\s?(AM|PM)?$` (`Importers.swift:65-67`). Matches `10:42`, `10:42 AM`, `10:42AM`, `9:05 PM`, `24:99`; not `10:42 am`, `10:42:15`, `10:42  PM`, `at 10:42` (run). On the tested system `\d` also accepts non-ASCII numerals and `$` is the very end of the string (D18).

Observed (fixture 26; run): lower-case `shared by`, `report`, `Copy code`, `Claude is ...` survive; three equal lines separated by blank lines become one; a furniture line between two equal lines does not reset the comparison.

#### 2.5.4 Generic text

`parseGenericText`, `Importers.swift:347-388`.

```text
role = none; lines = []
for each line of text:
    if roleMarker(line) gives (r, rest): flush(); role = r; if rest is not empty: lines.append(rest)
    else: lines.append(line)                                   // the raw line
flush()
if there is no message: messages = [(unknown, full trim(text))]          // also when that is the empty string (D8)
provider: l = lowercase(whole text)
          Claude if l contains "claude"; else ChatGPT if l contains "chatgpt" or "gpt-"; else Gemini if l contains "gemini"; else Other
title = full trim(title); if empty: "Imported session"

flush(): body = full trim(lines joined with "\n"); if body is not empty: append (role or unknown, body); lines = []
```

Text before the first marker becomes a message of role `unknown` (shown as "Note"). A marker with no text before the next marker produces nothing. `System:` produces role `system`, which is kept (unlike in the ChatGPT parser). The keyword scan sees the whole text, markers included, and matches inside longer words: `Claudette` gives Claude (run).

### 2.6 Capture results

The capture browser (capture.md) returns `turns`: the texts of `[data-index]` elements in index order, each non-empty; or ONE element holding `document.body.innerText` when the page has no such elements; or an empty array (`WebCapture.swift:146-186`). The importer cannot tell a real single turn from the whole-page fallback.

Glue (`Views/LinkCaptureView.swift:41-56`, `Views/ImportSheet.swift:133-151`):

```text
if turns is empty: stop                                      // status already "Nothing captured <U+2014> is the transcript visible in the page?"
if looksLikeSignInWall(turns): status = (text below); stop   // the sheet stays open, nothing is saved, no override
fallback = last path component of the URL, or the whole URL if that is empty
title    = inline trim(typed name) if not empty, else detected title if any, else fallback
parsed   = fromCapturedTurns(turns, title, URL as typed)
if parsed has no messages: status "No conversation content captured from the page."
else: insert; attach the PDF; status "Captured N turns from <host> <U+2014> original saved as PDF." (or "Captured N turns from <host>." without a PDF)
```

Wall status text: `That looks like a sign-in or landing page <U+2014> log in below (or wait for the conversation to appear), then press Capture again.` It is shown in a single-line status field that truncates (`Views/LinkCaptureView.swift:32-36`); at phone width only the first two or three words are visible, as `apple/screenshots/03-capture-browser-signin-guard.png` shows for another status.

```text
fromCapturedTurns(turns, title, sourceURL):                  // Importers.swift:201-233
    fallbackProvider = Claude if sourceURL contains "claude.ai", else Other
    if exactly one turn:                                     // "usually the whole-page fallback"
        s = parseText(turn, title)[0]                        // 2.2: no chrome stripping, no extra cleaning
        s.sourceURL = sourceURL
        if s.provider is Other: s.provider = fallbackProvider
        return s
    messages = []
    for each block in stripChromeTurns(turns):
        cleaned = full trim(cleanTranscriptLines(lines of block) joined with "\n"); skip if empty
        splitLeadingRoleMarker(cleaned) -> (role, text), else (unknown, cleaned)       // text may be empty (D8)
    return session(title, fallbackProvider, sourceURL, no date, messages)
```

Guards (`Importers.swift:133-198`):

```text
MARKERS = "sign in", "log in", "meet gemini", "google terms", "terms of service", "just a moment",
          "verify you are human", "welcome back", "your personal ai assistant", "cookie", "privacy policy"

looksLikeSignInWall(turns):
    joined = turns joined with "\n"
    hits = number of MARKERS that occur as a substring of lowercase(joined)     // each marker counts once
    if length(joined) < 1200: return hits >= 2
    if length(joined) < 2500: return hits >= 4
    return false

isChrome(text) = length(text) < 700 and (
        lowercase(text) contains "ai overview" or "can make mistakes" or "sign in"
        or at least 2 MARKERS occur in it )

stripChromeTurns(turns):
    drop turns from the front while isChrome(first); drop turns from the end while isChrome(last)
    replace the first remaining turn by stripLeadingHeaderLines(it)

stripLeadingHeaderLines(text):
    HEADER = "sign in", "log in", "created with", "conversation transcript", "shared conversation", "ai overview"
    remove leading lines, at most 12, while the line (inline trimmed) is empty,
        or is shorter than 90 characters and its lowercase form contains one of HEADER
    rest = full trim(remaining lines joined with "\n")
    return rest, or the unchanged text if rest is empty
```

Neither chrome stripping nor header-line stripping tells the user anything; the removed text is simply missing from the saved session.

Every threshold was confirmed at its boundary (fixtures 55 and 56): 1199 characters with 2 markers is a wall and 1200 is not; 2499 with 4 is and 2500 is not; 699 characters is chrome and 700 is not; an 89-character header line is removed and a 90-character one kept; a 13th header line stays; blank lines count toward the 12. The first remaining turn is full-trimmed even when no line is removed.

### 2.7 Provider, title and date by path

| Path | Provider | Title | Original date |
|---|---|---|---|
| ChatGPT JSON | always ChatGPT | conversation `title`, else `ChatGPT conversation` | `create_time` of the conversation, if a number |
| Puller Markdown | Claude if the `Source:` text contains `claude.ai`, else Other | text after `# ` (may be empty) | none |
| Share-page text | always Claude | as passed in | none |
| Generic text | keyword scan: `claude`, then `chatgpt` or `gpt-`, then `gemini`, else Other | as passed in, trimmed; `Imported session` if empty | none |
| Capture, several turns | Claude if the URL contains `claude.ai`, else Other | typed name, else detected title, else last path component, else the URL | none |
| Capture, one turn | as the text parser decides; if that is Other: Claude if the URL contains `claude.ai` | as above, but a puller-shaped page text overrides it with its `# ` line (run) | none |

"None" means the session's original date is set to the moment of import (`Importers.swift:443`). Bare time lines on share pages are deleted, not read. Message-level times are never kept; the Apple message model has no such field.

### 2.8 What is stored

`insert`, `Importers.swift:435-452`: one `ChatSession` (title, provider, model name, source URL, `createdAt = parsed date or now`) and one `ChatMessage` per message with `index` 0, 1, 2 ... in parser order, `role`, `text`. `modelName` is always empty: no parser sets it. Sessions are inserted in the order the parser returned them. Nothing is checked for duplicates. data-model.md covers the fields.

### 2.9 How a message is split for display

Not part of import: `MessageSegment.parse` runs every time a message is drawn (`Views/MessageView.swift:46-93`). The stored text is never changed.

```text
for each line of text (split at "\n"):
    t = inline trim(line)
    if inside code: if t == "```": close the block (code = collected lines joined with "\n") else collect the raw line
    else if t starts with "```": flush prose; language = inline trim(t without its first 3 characters) or none if empty; open a block
    else: collect the raw line as prose
at the end: an open block is closed as code; otherwise flush prose
flush prose: joined = lines joined with "\n"; emit it only if its full trim is not empty   // the emitted text is NOT trimmed
```

Each prose segment is then cut at blank lines into paragraphs, each trimmed, and rendered with inline Markdown only (`Views/MessageView.swift:110-123`): bold, italic, inline code and links work; headings, lists, tables and quotes appear as typed. Results for 22 edge cases are in fixture 57.

### 3.2 What the web app does instead

Rules W1 to W15. Where a rule says "as Apple", section 2 applies unchanged. The web expectations in `fixtures/import/` were generated from exactly these rules.

**W1. Normalise text at the boundary.** Apply to every string that enters the importer (decoded file text, pasted text, each captured string, each string taken out of JSON), before anything else: (1) remove one leading U+FEFF; (2) replace CR LF by LF, then every remaining CR by LF; (3) remove U+0000; (4) replace lone surrogates by U+FFFD (`toWellFormed()`). Do not apply Unicode normalisation (NFC or NFD): fixture 23 has both forms of an accented letter and expects them back unchanged. After W1 no CR exists anywhere, so the CRLF fixtures (02, 14, 27) must give exactly the result of their LF twins (01, 13, 26).

**W2. Decode bytes explicitly.** In this order:

```text
0 bytes                                   -> rejected, empty_input
starts with EF BB BF                      -> UTF-8, strict
starts with FF FE / FE FF                 -> UTF-16LE / UTF-16BE; flag decoded_as_utf_16le / decoded_as_utf_16be
no byte-order mark: look at the first min(length, 4096) bytes, rounded down to an even count, as pairs:
    zero in >= 40% of the second bytes and in <= 5% of the first bytes -> UTF-16LE (flag); the mirror image -> UTF-16BE (flag)
strict UTF-8 succeeds                     -> UTF-8          // new TextDecoder("utf-8", { fatal: true })
any byte below 0x20 other than 09, 0A, 0C, 0D -> rejected, undecodable (binary data)
otherwise                                 -> windows-1252; flag decoded_as_windows_1252
then W1; if only white space is left      -> rejected, empty_input
```

A flag means "tell the user which encoding was assumed". Never use `File.text()`, `Blob.text()` or a non-fatal `TextDecoder` for import: they replace invalid bytes with U+FFFD without telling anyone. `JSON.parse` rejects a leading U+FEFF, so W1 has to run before it (fixture 08). Fixtures 03, 08, 18, 24, 25.

**W3. JSON files.** For a file whose extension is `json` (any letter case): parse the decoded text. A document with `"format": "sessionvault-interchange"` goes to the interchange import of data-model.md section 6.7 and never reaches the rules below. Otherwise try the ChatGPT export (2.5.1 with W4). Not that either, or not valid JSON: rejected with `unrecognised_json`. A recognised export without any message: rejected with `no_messages`. The raw JSON text is never imported silently; the user interface may offer "keep as a plain-text note", which then calls the text path on purpose. Fixture 12. The puller's `<id>.json` (the largest JSON response seen while the page loaded, `puller/pull_sessions.py:185-189`) has no schema documented anywhere in the repository; it falls under this rule until someone documents the schema from a real file.

**W4. ChatGPT export, robust.** As 2.5.1 with these changes: a top-level array may contain anything; entries that are not objects with a `mapping` object are skipped, and the file is this format if at least one entry qualifies (fixture 09). Keep a set of visited ids while walking `parent`; stop at the first repeat (fixture 10). If the walk from `current_node` collects nothing, use the time order. Time order = stable sort by `message.create_time` (a number, else 0), ties in the order of the keys in the JSON text (fixture 11; JavaScript keeps that order for keys that are not integers). Title: trim, then the fallback. `create_time` counts only when it is a finite number; keep milliseconds. Apply W1 to the joined parts before the full trim. Sessions are returned in file order.

**W5. Puller Markdown.** As 2.5.2 with these changes:

```text

a "header pair" is a line starting with "# " followed directly by a line starting with "Source: "

walk the lines; a header pair starts a NEW session whenever it appears at the start of a block,
    that is, when only blank lines have been seen since the last "---" line or since the previous header pair

### 3.3 Weaknesses kept on purpose

These follow from the heuristics themselves. The web app keeps them, and the user interface has to make them visible.

1. The wall and chrome tests match substrings. Real first or last turns can still be dropped (fixture 43) and real short chats can still be flagged (fixture 45). Hence `dropped_turns` and `allow_wall`.
2. Outside fenced blocks the cleaner still removes an unindented line equal to the one before it, the five exact furniture words, and bare time lines (fixture 28 shows all three).
3. A line that starts with `User:`, `System:`, `AI:`, `Me:` or `You:` outside code starts a new message, whatever the writer meant.
4. In the share-page parser any line that starts with `You said:` starts a turn.
5. Harvested turns have a role only when their first line is a marker; otherwise `unknown`, shown as "Note".
6. An unbalanced fence pairs with the next bare fence line and hides the markers between them.
7. Page text with no label lines cannot be split from text alone (fixture 48). That needs page structure: capture.md.

W1 runs in the import module, not in the input control. |
| C4 | One module, two places | The same pure module runs in the browser (preview, share target, offline) and on the server (authoritative import). It may use `Intl.Segmenter`, `URL` and `TextDecoder` (with the labels `utf-8`, `utf-16le`, `utf-16be`, `windows-1252`), which exist in browsers, workers and Node 18+ (checked here in Node 25 only); nothing from the DOM or from Node. |
| C5 | Storage | PostgreSQL `text` rejects U+0000, and lone surrogates cannot be stored as UTF-8; W1 removes both (data-model.md C9). A single message can be a megabyte: raise the JSON body limit of the import routes and send one session per request (web-platform.md 11.5). |
| C6 | Large input | The Apple app has no limits (2.10). A ChatGPT export can be hundreds of megabytes (inference). Parse in a Web Worker, read `file.size` first, and apply the limits web-platform.md 6.2 suggests. The parent-cycle fixture (10) matters more on a server: an import that never returns is a denial of service. |
| C7 | Untrusted text | Everything imported can come from a web page. Never insert it as HTML. `source_url` comes from the input (the `Source:` line, a pasted link): show it as a link only if it parses as `http:` or `https:` (data-model.md C12). The Apple app links any string that parses as a URL. |
| C8 | Confirm before saving | The Apple app saves at once. The web result object carries things a person has to see first: `sign_in_suspected`, `dropped_turns`, an assumed encoding, `unrecognised_json`, a single message of role `unknown` from a capture (a page that could not be split). Show a short preview with these before the save, or save and show them with undo. Wording and layout: design.md. |
| C9 | Batches | Parsers return sessions in file order. data-model.md (B7) describes how to keep that order in the list. Report each file of a multi-file import separately: name, number of sessions, or the reason. |
| C10 | Duplicates | Importing the same file twice makes two sessions in the Apple app. data-model.md (B2) suggests a warning when source URL and message count match an existing session; a hash of the normalised message texts is a stronger test. |
| C11 | Keeping the input | Cleaning and splitting are lossy heuristics that will be corrected over time. Keeping the original input (the pasted text, the file bytes, the captured strings) with the session, plus the parser version, would allow re-parsing later. This costs storage and keeps more private text; it is the owner's decision (section 7). |
| C12 | URL parsing | `new URL()` is not Foundation's `URL(string:)`: `new URL("https://3.14").hostname` is `3.0.0.14` (run in Node), for example. Use `looksLikeLink` (W11), not a port of the Apple test. |

## 5. Shape of the module and of a result

Suggested exports (names are free; the fixtures only need a mapping, see `fixtures/import/README.md`):

```ts
normaliseText(text: string): string                                            // W1
decodeBytes(bytes: Uint8Array): { text: string; flag: string | null } | null   // W2
parseText(text: string, title: string): ParsedSession[]                        // context pack (optional), puller, share page, generic
parseChatGPTExport(json: unknown): ParsedSession[] | null                      // null = not this format, [] = no messages
importFile(bytes: Uint8Array, filename: string): ImportResult                  // W2, W3
importPaste(text: string, options: { title: string; pickerProvider: Provider; sourceUrl?: string; allowWall?: boolean }): ImportResult   // W11
importCapture(input: { sourceUrl: string; detectedTitle: string | null; typedName: string; kind: "page-text" | "turns"; turns: string[]; allowWall?: boolean }): ImportResult   // W10
looksLikeSignInWall(turns: string[]): boolean
stripChromeTurns(turns: string[]): { kept: string[]; dropped: DroppedTurn[] }
```

`ParsedSession` = title, provider (`claude`, `chatgpt`, `gemini`, `other`), model, source URL, original date or none, messages of role and text. It is what data-model.md section 8.6 takes. `ImportResult` = outcome (`imported`, `rejected`, `link`), reason, flags, sessions, and for captures the dropped turns.

Where a port of this code typically goes wrong:

- Using `length`, `trim()` or `\s` where 2.3 says otherwise (fixtures 23 and 55 catch it).
- Reading files with `File.text()` or `readFileSync(path, "utf8")`. Both hide encoding problems and leave a byte-order mark in the string. Decode with W2, then W1, then parse.
- Testing against a `*.expected.apple.json` file. Those record defects. Likewise, do not reproduce empty messages, zero-message sessions or raw-JSON notes; check the kind of the fixture.
- Guessing `kind` from the number of turns (W10) or the provider from words in the text (W9).
- Changing the order of the steps on a captured turn. It is: header lines, chrome test (both on the raw turn), then the cleaner, then the full trim, then the leading marker.
- Sorting ChatGPT nodes with an unstable sort, or relying on the key order of an object whose keys look like integers (JavaScript moves those to the front).
- An import that can run forever or without bound on hostile input (fixture 10), on a server shared with everything else.
- Letting an editor, a formatter or git change the fixture bytes.
- Rendering imported text, or `source_url`, as trusted HTML or as a link without checking the scheme (C7).

Order of work that the fixtures support: (1) the primitives of 2.3 and W1, W2; (2) markers and the generic parser (fixtures 13 to 23); (3) puller Markdown (01 to 06); (4) ChatGPT export (07 to 12); (5) the cleaner and the share-page parser (26 to 30); (6) paste glue (31 to 38); (7) guards and capture (39 to 56); (8) display (57).

## 6. If instead ...

- **If the vault lives only in the browser (IndexedDB, no server):** the module runs in the browser only and nothing is re-parsed on a server. W1 step 3 (NUL) is then harmless rather than necessary. C5's request limits disappear; storage quota takes their place, which makes C11 (keeping the input) more expensive. Everything else in this document is unchanged.
- **If the API key is kept in the browser:** no effect on import.
- **If the stack is not TypeScript:** 2.3 is the part to re-check. Any language whose string length counts bytes or UTF-16 units needs a grapheme segmenter for W15, and its regular-expression `\s` and `\d` need the same care as in W7.

## 7. Open points

Not verified here:

- Nothing in this document was checked against a live page of any provider (no network). The share-page furniture strings, the `ChatGPT said:` header and the Gemini label lines are taken from the Apple code, from an earlier review, or from general knowledge.
- The schema of the puller's `<id>.json` is unknown (W3).
- The Apple results were produced on macOS 27.2.1. Older systems may evaluate the time-line regular expression differently (D18); nothing else depends on the system.
- `Views/ImportSheet.swift` and `Views/LinkCaptureView.swift` were read and transcribed, not executed.

Decisions for the owner:

1. When a transcript comes with no link and no assistant name among its speaker labels, the Apple app guesses the provider from words in the text; that guess is what mislabelled the Gemini captures. This document drops the guess (W9): such imports are labelled by the picker (paste) or `Other` (files) until the user changes it. Is that acceptable?
2. Should the web app keep the original input next to each imported session so that it can be re-parsed when the rules improve (C11)?
3. Should a pasted context pack be importable (W14), or is the interchange format enough?
4. Should the web app save immediately, as the Apple app does, or always show the preview of C8 first?
5. The split rule for Gemini pages (the whole-line labels in W6) rests on a description of the owner's captures, not on a page anyone has looked at for this document. May the text of one such page be inspected once to confirm or correct the rule? Until then it is a guess that fails safe.
6. Is importing the puller's `<id>.json` files wanted? If so, one real file is needed to document its structure (W3); none is in the repository and none was read.
